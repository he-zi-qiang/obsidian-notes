# 正向测试
>验证接口在正常输入下能否返回预期结果

- 单参数合法值：每个参数传入符合要求的值
- 多参数组合：所有必填参数都传入合法值，验证完整流程
- 典型业务场景：模拟真实用户操作（如：创建文章 → 发布 → 查看）

---

# 反向测试
>验证接口在异常输入下能否正确处理并返回合理的错误信息

### 参数缺失
- 必填参数不传
- 必填参数传空字符串 `""`
- 必填参数传 `null`

### 参数类型错误
- 数字字段传字符串（如 `"abc"` 传给 `page` 参数）
- 布尔字段传数字
- 数组字段传对象

### 参数值非法
- 不在枚举范围内的值
- 负数（如分页 `page=-1`）
- 特殊字符 / SQL注入片段 / XSS脚本

### 权限相关
- 未登录访问需要认证的接口
- 普通用户访问管理员接口
- 使用过期 token

# 边界测试
>验证接口在边界值上的表现

### 字符串边界
- 空字符串 `""`
- 最小长度（如1个字符）
- 最大长度（如标题限制255字符）
- 超出最大长度

### 数值边界
- 最小值（如 `0` 或 `1`）
- 最大值（如 `Integer.MAX_VALUE`）
- 超出范围的值

### 分页边界
- `page=0` 或 `page=1`（取决于是否从0开始）
- `size=0`
- `size=1`
- 超大 size（如 `size=99999`）
- 超出总页数的 page

### 集合/数组边界
- 空数组 `[]`
- 只有一个元素
- 大量元素

# 常用设计方法

### 等价类划分
>将输入数据划分为若干等价类，从每个类中选一个代表值
- 有效等价类：符合要求的输入
- 无效等价类：不符合要求的输入
- 例如：用户名长度要求3-20字符 → 有效类(5字符)、无效类(1字符, 25字符)

### 边界值分析
>重点测试边界附近的值
- 刚好等于边界值
- 刚好超出边界值（±1）
- 例如：年龄范围0-150 → 测试 -1, 0, 1, 149, 150, 151

### 场景法
>按业务流程串联多个接口，模拟完整业务场景
- 基本流（正常路径）
- 备选流（分支路径）
- 异常流（错误路径）
- 例如：注册 → 登录 → 创建文章 → 编辑 → 发布 → 删除

### 错误推测法
>根据经验推测容易出错的地方
- 并发操作（同时修改同一资源）
- 重复提交（连续点击两次创建）
- 数据依赖（删除被引用的数据）
