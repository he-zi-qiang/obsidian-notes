# 断言（核心）
>断言 = 验证接口返回的结果是否符合预期
>没有断言的测试只是"调接口"，不是"测接口"

---

## 1. 状态码断言
>最基本的断言，验证HTTP状态码

| 状态码 | 含义 | 场景 |
|--------|------|------|
| 200 | 成功 | GET请求成功返回数据 |
| 201 | 创建成功 | POST创建资源成功 |
| 204 | 无内容 | DELETE删除成功 |
| 400 | 请求错误 | 参数校验失败 |
| 401 | 未认证 | 没有传token或token过期 |
| 403 | 无权限 | 权限不足 |
| 404 | 不存在 | 资源未找到 |
| 500 | 服务器错误 | 后端代码异常 |

---

## 2. 响应体断言
>验证返回的JSON数据是否正确

### 字段值校验
- 某个字段等于预期值：`response.spec.title == "测试文章"`
- 某个字段不为空：`response.metadata.name != null`

### 字段类型校验
- 字段是字符串、数字、布尔值、数组、对象等
- 例如：`typeof response.spec.publishTime == "string"`

### 结构校验
- 返回的JSON是否包含预期的字段
- 嵌套结构是否正确
- 例如：响应中必须包含 `metadata`、`spec`、`status` 三个顶层字段

### 列表校验
- 列表长度是否符合预期：`response.items.length == 10`
- 列表中每个元素是否都包含必要字段
- 排序是否正确

---

## 3. 响应头断言
- `Content-Type` 是否为 `application/json`
- `Set-Cookie` 是否正确设置
- 自定义响应头是否存在

---

## 4. 响应时间断言
- 接口响应时间是否在合理范围内
- 例如：`responseTime < 2000ms`
- 用于发现性能问题

---

## 5. 业务逻辑断言
>超越单接口，验证业务是否正确

### 数据一致性
- 创建后查询，数据是否一致
- 修改后查询，字段是否更新
- 删除后查询，是否返回404

### 副作用验证
- 创建文章后，文章计数是否+1
- 删除分类后，关联的文章是否处理正确

### 数据库校验（进阶）
- 直接查数据库验证数据是否正确写入
- 通常在自动化测试框架中使用

---

## 6. Postman中的断言写法
```javascript
// 状态码断言
pm.test("状态码是200", function () {
    pm.response.to.have.status(200);
});

// 响应体字段断言
pm.test("返回的标题正确", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData.spec.title).to.eql("测试文章");
});

// 响应体包含字段
pm.test("包含metadata字段", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.have.property("metadata");
});

// 响应时间断言
pm.test("响应时间小于2秒", function () {
    pm.expect(pm.response.responseTime).to.be.below(2000);
});
```

---

## 7. 断言的原则
- **每个测试用例至少一个断言**：否则测试无意义
- **断言要具体**：不要只判断"不为空"，要判断具体值
- **正向和反向都要断言**：正向验证数据正确，反向验证错误码和错误信息
- **独立性**：一个断言失败不应影响其他断言的执行
