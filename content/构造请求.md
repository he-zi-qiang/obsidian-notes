# 构造请求
>接口测试的核心操作之一：按照接口文档的要求，组装一个完整的HTTP请求发送给服务器

---

## 1. 请求方法（Method）
| 方法 | 用途 | 示例 |
|------|------|------|
| GET | 查询资源 | 获取文章列表 |
| POST | 创建资源 | 创建新文章 |
| PUT | 全量更新资源 | 更新整篇文章 |
| DELETE | 删除资源 | 删除一篇文章 |
| PATCH | 部分更新资源 | 只修改文章标题 |

---

## 2. 请求URL
- 由 **Base URL + 接口路径 + 路径参数** 组成
- 示例：`https://api.halo.run/apis/content.halo.run/v1alpha1/posts/{name}`
- 路径参数用实际值替换：`/posts/my-first-post`
- `/login` 就像是商场一楼的"保安核验处"，路径当然越短越好找；而 `/apis/.../v1alpha1/posts` 就像是商场内部"3楼-A区-1号柜台-售卖的文章商品"，它需要精确定位你要找的具体东西。
	- 是"分组的"（group = content.halo.run）
	- 是"版本化的"
	- 是"资源化的"

	👉 这和：

	- Kubernetes
	- 云原生 API

	是同一套设计思想

---

## 3. 请求头（Headers）
### 常用请求头
- `Content-Type`：告诉服务器请求体的格式
  - `application/json`：最常见，JSON格式
  - `multipart/form-data`：文件上传
  - `application/x-www-form-urlencoded`：表单提交
- `Authorization`：认证信息
  - `Basic base64(username:password)`
  - `Bearer <token>`
- `Accept`：告诉服务器期望的响应格式
  - `application/json`

---

## 4. 请求参数
### Query参数（URL上的参数）
- 拼接在URL后面：`?page=1&size=10&keyword=halo`
- 通常用于GET请求的过滤、分页、排序

### Path参数（路径参数）
- 嵌在URL路径中：`/posts/{name}` → `/posts/my-first-post`
- 通常是资源的唯一标识

### Body参数（请求体）
- 通常用于POST/PUT/PATCH请求
- JSON格式示例：
```json
{
  "spec": {
    "title": "测试文章",
    "slug": "test-post",
    "allowComment": true
  }
}
```

### Form-data参数
- 用于文件上传场景
- 包含字段和文件两部分

---

## 5. 参数化与变量
>避免硬编码，让请求可复用

### 环境变量
- `{{base_url}}` → 不同环境切换（开发/测试/生产）
- `{{token}}` → 认证token

### 动态变量
- 从上一个接口的响应中提取值
- 例如：创建文章后提取 `name`，用于后续的查询/更新/删除

### 数据驱动
- 用CSV或JSON文件提供不同的测试数据
- 同一个请求模板跑多组数据

---

## 6. Halo实际示例
### 创建文章的请求
```
POST https://api.halo.run/apis/content.halo.run/v1alpha1/posts
Headers:
  Content-Type: application/json
  Authorization: Bearer <your-token>
Body:
{
  "spec": {
    "title": "我的测试文章",
    "slug": "my-test-post",
    "allowComment": true,
    "visible": "PUBLIC",
    "publish": false
  },
  "apiVersion": "content.halo.run/v1alpha1",
  "kind": "Post"
}
```
