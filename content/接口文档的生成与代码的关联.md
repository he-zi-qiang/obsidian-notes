# 接口文档的生成与开发流程
>对应流程图中的上层部分：接口测试在整个开发流程中的位置、接口文档如何产生

---

## 接口测试在开发流程中的位置

### 典型开发流程
```
需求分析 → 系统设计 → 编码开发 → 单元测试 → 接口测试 → 集成测试 → 系统测试 → 验收上线
```

### 接口测试的时机
- **开发完成后、前端联调前**：后端接口开发完毕，先通过接口测试验证正确性
- **前后端并行开发时**：前端根据接口文档开发，测试人员同步进行接口测试
- **每次代码变更后**：通过CI/CD自动执行回归测试
- **上线前**：完整跑一遍核心接口确保无问题

### 接口测试与其他测试的关系
- **单元测试**：开发自测代码逻辑 → 粒度最细
- **接口测试**：验证接口输入输出是否正确 → 中间层
- **UI测试**：通过界面验证完整业务流 → 粒度最粗
- 接口测试比UI测试更稳定、更快、更容易定位问题

## 接口文档如何产生

### 方式一：手动编写
- 开发人员用Markdown/Word/Wiki手动编写
- 缺点：容易和代码不同步，维护成本高

### 方式二：自动生成（Halo使用的方式）
- 开发人员在代码中写注解/注释
- 工具自动扫描代码生成文档
- 优点：文档和代码始终同步

---

## Halo的接口文档生成机制

### 使用的技术：SpringDoc + OpenAPI
- Halo基于Spring Boot开发
- 使用 **SpringDoc** 库自动生成 OpenAPI 规范的接口文档
- 文档地址：`https://api.halo.run`

### 生成流程
```
Java代码中的注解 → SpringDoc扫描 → 生成OpenAPI JSON/YAML → Swagger UI渲染为可视化页面
```

### 代码中的关键元素
- `@RestController`：标记这是一个接口控制器
- `@GetMapping` / `@PostMapping`：定义请求方法和路径
- `@RequestBody`：定义请求体参数
- `@PathVariable`：定义路径参数
- `@RequestParam`：定义查询参数
- `@Schema`：描述数据模型的字段信息

### 这就是"内容为什么是这样的"
- 接口文档中的**路径** ← 来自 `@GetMapping("/posts")`
- 接口文档中的**请求方法** ← 来自注解类型（Get/Post/Put/Delete）
- 接口文档中的**参数** ← 来自方法参数的注解
- 接口文档中的**数据结构** ← 来自Java类的字段定义和`@Schema`注解
- 接口文档中的**响应格式** ← 来自方法返回值类型

## 接口文档与实际代码的关联
- 文档是代码的"镜像"，不是独立存在的
- 如果文档和实际行为不一致，通常是文档（注解）需要更新
- 测试时发现文档与实际不符 → 这本身就是一个Bug，需要反馈给开发
